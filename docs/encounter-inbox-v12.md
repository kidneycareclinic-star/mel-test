# Encounter attention inbox v12

Saving reviewed text already queues encounter preparation. The header inbox now gathers the signed-in physician's current assigned encounter jobs across patients: ready, paused or expired work in Needs attention, queued/running work in Preparing. The follow-up dot also opens this inbox. Opening a card selects the patient, returns to the Office workspace and patient mobile pane, and focuses the existing encounter review.

An opaque `#review/<job UUID>` link contains no patient identity, chart text or session credential. It survives the sign-in screen and resolves only after authentication and assigned census loading. The endpoint checks active synthetic clinician identity, encounter ownership, patient assignment, practice membership, physician role, Office scope and read/draft permissions on every read and receipt. Server errors conceal unowned/unassigned records. Stale job links resolve only a replacement job for the same encounter; an older visit cannot open a different current visit. Signed links open their exact saved visit package. The coordinator additionally fences linked reads to an expected encounter ID, including polling, to handle changes between link resolution and review loading.

Mark seen records a private per-clinician navigation receipt. It does not change clinical state, source content, decisions, notes, prescriptions, orders, approval receipts or signatures. It compares the current event/status revision; a stale receipt fails rather than hiding new work. A subsequent failure/replacement/expiry becomes unseen. Seen work remains in the inbox until it is superseded, cancelled or finalized. Pagination is 50 items. Automatic refresh occurs on preparation transitions, finalization, tab visibility and every 30 seconds while visible.

The new `encounter-inbox-gated` function requires platform JWT validation plus actual clinician-session validation. Database receipt storage has RLS and all grants revoked from public/anon/authenticated; reads and writes use server-side connections with explicit IAM checks. Read and seen operations write clinician-linked access audit entries. No security-definer functions are introduced. Write bodies are stream-limited to 4 KB. CORS admits only the established preview and local development origins. Responses and client requests disable caching; session tokens remain in memory. Late responses from another clinician account are discarded.

Phone alert text is an in-app preview only. No phone provider, real PHI, SMS delivery, prescribing, external ordering or clinical release is configured. The inbox cannot finalize; finalization still requires the exact current reviewed packet and existing transactional authorization gates. This synthetic preview is not a production HIPAA attestation or clinical validation.

Verification covers real PostgreSQL ownership/assignment/role/scope checks, event receipts and idempotency, new-event re-alert, stale acknowledgements, same-encounter replacement, wrong-account/old-visit/signed links, expiration and pagination, body/session/origin gates, private RLS, unchanged clinical state, authenticated DOM routing, account-switch races, text-safe rendering and opaque links. Chromium renders the actual inbox and existing review in dark/light and at 760/390/320 px. Existing orchestration, source review and exact-packet finalization regressions remain in CI. Model responses in existing suites are synthetic mocks.
