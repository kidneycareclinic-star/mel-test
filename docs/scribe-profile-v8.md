# Scribe feedback and physician drafting v8

The reviewed transcript and dictation now append verbatim to the editable pre-charting note without replacing existing physician edits. The main patient screen renders that narrative separately from lab trends, using text nodes. Saving reviewed transcript or dictation also saves the encounter draft through the existing authenticated, versioned encounter gateway. A failure retains the local note and explicitly says it is not saved. Reload fetches the assigned clinician's saved draft; the latest signed note is shown as a labeled fallback without importing it as a new source. Audio itself remains in the tab for replay and is discarded on reload/patient switch; it is not stored in the application database.

A shared Web Audio analyser displays measured microphone amplitude history, recording state and elapsed time in recorded scribe capture, browser preview and physician dictation. It never connects microphone input to speaker output. Silence keeps the bars near baseline and displays a quiet microphone message. Missing analyser support shows an explicit unavailable message with a running timer. Stop, capture failure, patient switch, workspace close, pending permission cancellation and pagehide release microphone tracks and analyser resources.

Physician note preferences provide SOAP, problem-oriented, nephrology consultation or custom headings; brief, standard or detailed prose; and custom writing instructions. Both pre-charting and visit completion use the same profile. Remembered profiles are scoped to the authenticated user's ID on this browser and contain only template guidance. Patient notes and audio do not enter profile storage.

The new `note-drafting-gated` endpoint authenticates the real clinician and assigned synthetic patient with encounter.draft permission, then selects the owned saved draft or the exact owned signed encounter snapshot and draft completion package. Requests cannot supply replacement clinical sources. Only reviewed source text, selected chart context and explicitly approved completion items go to OpenAI Responses (`gpt-6-astra`, ultrafast, store:false); raw ASR provenance, unparsed attachments and other-encounter Astra reviews are excluded. Custom guidance cannot authorize new clinical facts or actions. Strict structured output is validated for headings and exact source excerpts; changed source versions, invalid quotes, partial/refused output and provider failures reject the draft. This is a documentation preview endpoint and makes no clinical writes.

Generation never overwrites the note. The physician can edit, inspect source excerpts, apply or discard the preview, then save through the existing draft/package gateway. Local note changes or patient switches block applying stale output. Approved visit packages stay immutable. The existing deterministic SOAP action remains a fallback. The pre-chart note limit remains 20,000 characters and source/raw text limits remain 6,000 characters each; save errors are visible, with local text retained.

Validation covers 24 synthetic source fixtures, four templates and three detail levels, custom guidance, source ownership, saved/signed source selection, missing data, exact quotes, source-version races, provider failures, real microphone sample-driven bars, cleanup, shared profiles, explicit preview application, local edit protection, immediate main-screen visibility and patient isolation. CI also runs the existing Postgres.js/PostgreSQL encounter/completion regressions. Provider prose and microphone samples are mocked in automated tests; they do not establish transcription accuracy or clinical quality. A physician should assess a known synthetic conversation against playback and the generated draft before judging reliability. No real patient audio is used.

Deployment status: the physician explicitly approved sending reviewed synthetic encounter text and chart context to OpenAI on October 4, 2026. `note-drafting-gated` is deployed with JWT verification and clinician/assignment checks. The preview sets `SYNTHETIC_NOTE_DRAFTING_ENABLED=true` before loading the drafting UI. Both pre-charting and draft visit packages can generate an editable preview; applying and saving remain explicit physician actions. The client stays closed when the configuration is absent or disabled, with a no-transmission regression test. Existing audio transcription remains enabled under its prior approval.
